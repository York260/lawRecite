# 雙人對決模式：技術規劃（Firebase）

> 狀態：規劃稿，尚未實作。目標是用最少的伺服器流量與連線數，做出即時的「答對一字 → 火球轟對方 → 血量先歸零者輸」對戰。

## 1. 玩法

- 兩人進入同一個房間，背**同一條**（或同一串條文，由房間的亂數種子決定順序），模式、挖空程度、輸入方式各自可選（注音或語音都行）。
- 雙方各 **100 HP**。自己每答對一個字 → 發出一顆火球，扣對方血。
- **連擊加成**：連對 10 字以上每字 ×1.5、20 字以上 ×2；打錯會中斷連擊。
- 打錯不扣自己血（避免新手被雙重懲罰），但會中斷連擊。用「提示」不造成傷害。
- 傷害設計成「完整背完一條約可打掉對方 60～70 HP」，一場通常 2～3 條、1～3 分鐘結束。
- 血量歸零即輸；雙方都背完條文串時，剩餘血量多者勝。

## 2. 為什麼選 Realtime Database，不用 Firestore

| | Realtime Database (RTDB) | Firestore |
|---|---|---|
| 計費方式 | 依**下載流量**與儲存量 | 依**每次讀寫次數** |
| 一場對戰約 600 次小寫入 | 只算幾十 KB 流量 | 600 寫入＋對手 600 讀取，很快吃掉每日免費額度 |
| 延遲 | 很低，適合遊戲 | 稍高 |
| 斷線處理 | 內建 `onDisconnect()` | 需要自己處理 |

結論：**對戰狀態放 RTDB**。若之後要做排行榜（低頻、要查詢排序），才考慮 Firestore 或 RTDB 的 `orderByChild` + `limitToLast`。

## 3. 省流量的核心設計

### 3.1 只同步「兩個累計數字」，不傳事件
每位玩家只寫自己的節點：

```
rooms/{code}/p/{uid} = { d: 累計造成傷害, n: 已完成字數, f: 是否背完 }
```

- **不傳每一下按鍵、不傳火球事件、不傳條文內容**。條文資料兩邊本來就都有（`data/laws.js`）。
- 對手的血量由各自的手機本地計算：`我的血量 = 100 - 對手.d`。
- 火球動畫也在本地觸發：看到對手的 `d` 從 37 變成 41，就播放對應數量的火球飛向自己；自己的 `d` 增加時，播放火球飛向對手。
- 因為是**累計值**，封包掉了或晚到都不會錯，下一筆就自動補齊（冪等）。

### 3.2 節流合併寫入
- 答對時只更新本地數字，**每 250ms 最多寫一次**；期間的多次答對合併成一次寫入（只送最新值）。
- 一個人打字最快每秒約 4～6 字 → 每秒最多 4 次寫入，每次約 40～60 bytes。
- 換算：一場 2 分鐘 ≈ 每人約 400 次寫入 × 50 bytes ≈ 20 KB，對手下載也約 20 KB。

### 3.3 只監聽需要的路徑
- 只訂閱 `rooms/{code}/p/{對手uid}`，不訂閱整個房間，不重複下載自己的資料。
- 對戰結束立刻 `off()` 解除監聽。

### 3.4 不在對戰時才連線
- **Firebase SDK 延遲載入**：只有按下「對決」才從 CDN 載入 `firebase-app` + `firebase-auth` + `firebase-database`（約 100KB gzip），平常背誦完全不連 Firebase。
- 離開對決畫面就 `goOffline()`。RTDB 免費方案限制 **100 個同時連線**，這樣只有正在對戰或等待中的人才佔用名額。

### 3.5 開局同步不靠來回確認
- 房主寫入 `startAt = 伺服器時間 + 3 秒`（`ServerValue.TIMESTAMP`），雙方用 `.info/serverTimeOffset` 校正本機時間後各自倒數，**不需要來回訊息就能同時開始**。

### 3.6 房間自動清理（不需 Cloud Functions）
- Cloud Functions 需要付費方案（Blaze），所以改用：
  - `onDisconnect().remove()`：玩家斷線時自動移除自己的節點；房主斷線時移除整個房間。
  - 結束後由最後離開的人刪除房間。
  - 建房時順手清掉自己舊的房間。
- 儲存量因此長期接近 0。

## 4. 資料結構

```
rooms/
  {code}/                      # 4 碼房號，例如 7K2Q（排除易混淆的 0/O、1/I）
    host: uid
    cfg: { law, arts: [...條文id], mode, density, seed }
    startAt: 伺服器時間戳
    p/
      {uid}: { name, d, n, f, hp? }   # 只有本人能寫
```

## 5. 安全規則重點（[`firebase/database.rules.json`](../firebase/database.rules.json)）

- 只能寫自己的玩家節點：`auth.uid === $uid`。
- `d`、`n` **只能遞增**，且每次增加量有上限（例如一次最多 +12），擋掉直接改成 999 的作弊。
- `n` 不可超過條文總字數；`startAt` 之前不能寫 `d`。
- 房間最多 2 人：寫入新玩家前檢查 `p` 的子節點數。
- 這是「朋友間對戰」等級的防作弊；要做公開排行榜時，需要再加伺服器端驗證。

## 6. 登入

- 使用 **Firebase 匿名登入**：打開就能玩，不用註冊；暱稱存在本機。
- 之後若要排行榜、跨裝置保存，可升級成 Google 登入（匿名帳號可直接綁定，不會遺失紀錄）。
- 需在 Firebase 後台把 `york260.github.io` 加入授權網域。

## 7. 配對方式

1. **房號邀請（第一版）**：建立房間 → 顯示 4 碼房號與分享連結（`…/lawRecite/#duel-7K2Q`），對方點連結直接加入。
2. **快速配對（之後）**：`queue/` 下排隊，用 transaction 兩兩配對。流量同樣很小，但要多處理排隊逾時。

## 8. 畫面與特效

- 上方雙血條（我／對手），對手名稱與即時完成字數。
- 答對時：火球從目前的字飛向對手血條（CSS `transform` + `offset-path` 或 Canvas，GPU 合成，不影響打字流暢度）；命中時血條晃動、數字跳動。
- 被打時：畫面邊緣紅光閃一下、輕微震動（有開「按鍵震動」時）。
- 連擊 10／20 時火球變大、變色。
- 尊重「減少動態效果」系統設定：改成只顯示數字變化。
- 結算畫面：勝負、雙方正確率、最高連擊、「再來一場」。

## 9. 免費額度估算（Spark 方案）

| 項目 | 限制 | 每場用量 | 可支撐 |
|---|---|---|---|
| 同時連線 | 100 | 2 | 同時 50 場 |
| 下載流量 | 10 GB／月 | 約 50 KB | 約 20 萬場／月 |
| 儲存 | 1 GB | 結束即刪 | 幾乎為 0 |

一般同學、讀書會規模完全在免費範圍內。同時超過 50 場時才需要升級 Blaze（依用量計費，這個流量級距仍很便宜）。
